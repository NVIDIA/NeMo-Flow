This page contains the release notes for [NVIDIA NeMo
Relay](/about-nemo-relay/overview).

Complete, pull-request-by-pull-request release history is available in
[GitHub Releases](https://github.com/NVIDIA/NeMo-Relay/releases).

## Release 0.9.0

NeMo Relay 0.9 is under development. These notes summarize user-visible changes
from 0.8.4 through current main.

### Highlights

- Managed daemon deployments share a broker across coding-agent sessions while
  keeping each machine-user identity's plugins and runtime in a separate worker.
- Pi joins the CLI integrations with persistent extension installation,
  lifecycle telemetry, tool-call policy, and supported model routing.
- Plugin initialization and validation use one core-owned host across language
  bindings, with explicit activation ownership and resolved configuration reports.
- Default propagation preserves trace continuity, and OpenTelemetry tool spans
  include richer execution metadata and sanitized GenAI tool content.

<Warning title="Breaking Changes">

Before upgrading, migrate plugin-host callers and tool execution intercepts,
review trace boundaries and PII redaction, and replace remote plaintext trace
endpoints with HTTPS. OTLP/HTTP trace exporters no longer follow redirects. See the
[Migration Guides](/reference/migration-guides) for required actions.

</Warning>

### Managed Daemon Deployments

- `nemo-relay daemon` provides a shared route broker with authenticated MCP
  clients, per-machine-user workers, and administrator-managed coding-agent
  bundles for Codex, Claude Code, and Pi. Workers load system configuration.
- MCP clients and workers use persistent WebSocket control sessions for route
  updates, readiness, draining, and recovery. Provider and hook traffic uses
  separate HTTP connections, with incremental response streaming.
- Local deployments support Windows, macOS, and Linux. Remote deployments use
  HTTPS and require the daemon to reach client workers. Platform service,
  provisioning, upgrade, and troubleshooting guides are available under
  [Daemon](/daemon/about).

### Coding-Agent and Framework Support

- Use `nemo-relay install pi`, `nemo-relay pi`, and `nemo-relay doctor pi` to
  install, launch, and diagnose the Pi extension. The integration is a proof
  of concept verified against Pi 0.84.x. It forwards session, turn, tool, and
  inline-shell activity and applies policy at supported hook boundaries.
- Relay-launched Pi model requests can select named upstreams automatically.
  Models using unsupported APIs or incompatible provider-wide endpoint layouts
  are not redirected. See [Pi](/nemo-relay-cli/pi).
- Standalone LangGraph `ToolNode` calls can use `create_tool_node` for managed
  tool execution while preserving state, store, and runtime injection. Combine
  it with `NemoRelayCallbackHandler` for graph lifecycle scopes. See
  [LangGraph](/supported-integrations/langgraph#managed-toolnode-calls).
- The OpenClaw plugin now targets OpenClaw 2026.9.3 and declares that version
  as its minimum gateway version. See
  [OpenClaw Plugin](/supported-integrations/openclaw-plugin).

### Plugin Configuration and Caching

- `initialize` and `validate` resolve the same static and dynamic plugin
  configuration, compatibility, and trust policy. Exact validation checks only
  the supplied static document. Initialization returns a `PluginHostActivation`
  that owns plugin lifetime. See
  [Configure and Initialize Plugins](/configure-plugins/initialize-plugins).
- Host reports include `config_paths` and a redacted `resolved_config`, making
  inherited and programmatic configuration visible without exposing literal
  credentials or opaque dynamic-plugin values.
- Response caching adds `key_strategy = "logical"`. It ignores tool-description
  changes and tool-list ordering while retaining other tool-definition
  differences. `exact_request` remains the default; the two strategies use
  separate cache keyspaces. See
  [Response Cache](/configure-plugins/adaptive/response-cache#key-strategies).

### Observability and Redaction

- Scope-stack forks and default propagation capture preserve the Relay root
  when one is available. Related work can continue the same OpenTelemetry
  trace across stacks and processes. Explicit rootless capture remains available.
- ATIF uses the propagated root for its serialized `session_id` when present.
  `trajectory_id`, filenames, remote storage keys, and remote session headers
  remain tied to the individual trajectory scope UUID.
- Claude Code, Codex, and Pi supply consistent tool type and executing-agent
  metadata, including known subagent ownership. The `gen_ai` projection adds
  sanitized JSON-object tool arguments and successful results, plus tool
  definition identities, by default. The `full` and `openinference` projections
  also receive the richer instrumentation metadata. See
  [OpenTelemetry](/configure-plugins/observability/opentelemetry).
- Direct trace, log, and metric subscribers accept environment-backed exporter
  headers through `header_env` (`headerEnv` in Node.js). Values are resolved
  when the subscriber is constructed; missing or invalid values fail
  construction without disclosing the secret.
- The PII `trajectory_context` preset now discards opaque payloads and unknown
  fields while retaining approved normalized analytics and trace parentage.
  Typed metric attributes require explicitly allowed string names and values;
  numeric, boolean, and unlisted attributes are dropped. See
  [PII Redaction Configuration](/configure-plugins/pii-redaction/configuration).

### Support Matrix and Compatibility Updates

The [Support Matrix](/reference/support-matrix) is the canonical reference for
supported platforms and architectures, worker runtimes, coding agents, and
integrations. Go and the raw C FFI remain experimental and source-first.

Migration guidance for upgrading from 0.8.x to 0.9 is available in the
[Migration Guides](/reference/migration-guides).

### Breaking Changes

- Tool execution intercepts now receive `(ToolExecutionContext, next)` instead
  of separate tool-name and argument parameters. The context includes the tool
  name, incoming arguments, and optional `tool_call_id`. Update callbacks across
  bindings and plugin SDKs. Context-aware native plugins use ABI v5; native and
  worker plugins registering this surface must declare a Relay range excluding
  0.8. See [Tool Execution Context](/reference/tool-execution-intercept-outcomes#tool-execution-context).
- Global plugin clear/report functions and explicit dynamic activation-spec
  APIs are removed. Retain the activation handle, read its unified report, and
  close it during shutdown. Static diagnostics now live under `report.config`;
  use exact validation when file discovery is not intended.
- Dynamic-plugin attestation runs in the core host for every embedding API.
  Omitted policy fields default to `startup = "required"` and
  `attestation = "signature_required"`. Unsigned plugins previously accepted
  by an embedded host can now fail startup.
- Python plugin-host initialization and activation raise `ValueError` for
  invalid static configuration and `FileNotFoundError` for unavailable
  referenced configuration or resources, replacing `RuntimeError` for those
  failures.
- Default propagation can join traces that were previously separate. ATIF
  consumers must distinguish a run-scoped `session_id` from the
  trajectory-specific `trajectory_id`.
- All trace projections require HTTPS for remote collectors with either HTTP
  or gRPC transport. Plain HTTP is limited to localhost and loopback IPs.
  OTLP/HTTP trace exporters reject redirects, including HTTPS redirects.
  Log and metric exporters retain their existing transport behavior.
- GenAI tool content is exported by default after sanitization. Review redaction
  policy before sending the additional content to collectors.
- The stricter `trajectory_context` preset removes previously retained opaque
  and metric fields. Update analytics that depend on them.
- Rust `ResponseCacheConfig.key_strategy` now uses `ResponseCacheKeyStrategy`
  instead of `String`; the `KEY_STRATEGY_EXACT_REQUEST` constant is removed.

### Fixed Known Issues in 0.9

- OpenTelemetry exports create valid local roots when a parent scope is not
  exported. Imported parent context survives asynchronous dispatch and event
  transformations without inventing remote parents for local scopes.
- Coding-agent LLM events preserve an explicit provider conversation ID or
  fall back to the resolved logical harness session ID for correlation.
- LangChain serialization preserves message boundaries, tool-call identity,
  and provider-native content blocks across middleware. Relay headers are
  omitted for models whose SDK rejects `extra_headers`, allowing those calls
  to proceed.
- Anthropic usage survives split streaming events, and gateway routing
  normalizes upstream URLs that already end in `/v1`. Stream aggregation also
  preserves Anthropic compaction content and encrypted content supplied in
  `compaction_delta` events.
- OpenAI Responses decoding preserves Codex automation tool outputs. Codex
  launch routing also remains scoped to the launched execution.
- Codex installation tolerates dangling marketplace registrations, and
  `nemo-relay install codex --force` can recover Relay-owned stale registrations.
- Generated Codex and Claude Code hook commands use private files. Pi tool
  results preserve their original text in lifecycle telemetry.
- PII URL masking no longer retains credentials, and overlapping PII path
  selectors no longer remove unrelated request content.

### Other Improvements

- Unix and PowerShell uninstall scripts remove a script-installed CLI while
  preserving configuration and integrations. They check active processes and
  refuse removal while managed daemon processes use the selected binary.
  See [Remove a Script-Installed CLI](/getting-started/installation#remove-a-script-installed-cli).
- ATIF documentation now clarifies that metadata placeholders are sanitized
  into individual path components; slashes in metadata values do not create
  nested directories. See [Metadata-Based Paths](/configure-plugins/observability/atif#metadata-based-paths).

## Known Issues in 0.9

- OTLP collectors can return a successful response while rejecting individual
  spans, log records, or metric data points. Relay does not report these partial
  successes in runtime diagnostics, and flush or shutdown can still succeed.
  Monitor collector-side rejection metrics and logs; see
  [OpenTelemetry](/configure-plugins/observability/opentelemetry#trace-batch-processor-configuration).
- Go and the raw C FFI remain experimental and source-first. Generated API
  pages focus on Rust, Python, and Node.js.
- Local coding-agent observability depends on host hooks and provider traffic
  reaching the local gateway. Relay cannot fully capture remote or cloud
  execution that bypasses the local host.
- Persistent Codex and Claude Code integrations use user-scoped
  configuration and a shared loopback gateway. Use `nemo-relay run` when a
  launch must retain project-specific configuration.
- On Windows, a restrictive host Job Object can limit gateway reuse or prevent
  persistent bootstrap. Codex can also make a cold-start `/models` request
  before required MCP servers start; Relay retries the request.
- Codex 0.143 does not expose `SessionEnd`, and Codex multi-agent v2 encrypts
  delegated-task payloads that Relay cannot decrypt or reliably link.
- Pi support is a proof of concept verified against 0.84.x. Its personal
  extension fails open by default, later extensions can rewrite authorized
  arguments, and unsupported provider routes produce no LLM spans. Nested Pi
  processes appear as separate sessions, and headless SIGINT can bypass queue
  draining. See [Pi Limitations](/nemo-relay-cli/pi#limitations).
- Managed daemon worker activation failures can put an authenticated route into
  pass-through until all MCP references leave. Pass-through forwards provider
  traffic without worker plugins; MCP readiness alone does not prove policy or
  exporter coverage. See [Daemon Operations](/daemon/operations).
- Remote daemon deployments require bidirectional reachability to client workers
  and WebSocket-capable proxies. Loopback control sessions have no periodic
  ping, so an idle hung process may remain undetected until an operation times out.
- The Node.js binding and package workflows require Node.js 24 or later.
- OpenClaw has public hook-backed telemetry. Its security and optimization
  coverage is partial because it does not own a managed execution path.
- The built-in `nemo_guardrails` plugin is deprecated and scheduled for removal
  in NeMo Relay 0.9. No replacement is included. Until removal, the remote
  backend inherits its configured service's availability, latency, and policy
  behavior, and the local backend requires Python 3.11 or later and
  `nemoguardrails==0.22.0`. Removal will include the built-in component kind,
  the public `nemo_relay::plugins::nemo_guardrails` Rust module, its CLI editor
  entry, and the `guardrails-remote` Cargo feature.
- The PII redaction plugin currently supports its deterministic local backend;
  local-model backend configuration is reserved for future work.
- Pricing and optimization estimates depend on model names, token data, pricing
  sources, and freshness evidence. Missing or inconsistent evidence produces
  partial or absent cost fields rather than zero values.
- ATOF stream sinks and remote ATIF storage require reachable, correctly
  configured destinations. A failed stream sink does not stop file output or
  other active sinks.
- ATIF omits point-in-time marks. Use ATOF for the canonical mark stream;
  the `gen_ai` OpenTelemetry projection also omits marks. The `full` and
  `openinference` projections retain their fixed native mark handling.
- Native dynamic plugins run in the Relay process and are not sandboxed. A
  `grpc-v1` worker runs in a separate process, but that process is not a
  security sandbox.
- Treat Python `LLMRequest` objects as immutable. Request middleware that
  changes content must return a new request object.
- Native subscriber callbacks arrive asynchronously. Flush subscribers before
  depending on their side effects, captured events, files, or exporter output.
- OpenTelemetry endpoints use finite batch queues. A burst that fills an
  endpoint queue drops completed spans without applying backpressure and can
  leave an incomplete trace, including a missing root span. The SDK warns on
  the first drop and reports the exact dropped-span count during graceful
  shutdown. Configure `max_queue_size`, `max_export_batch_size`, and
  `scheduled_delay_millis` independently on each endpoint, or use the standard
  `OTEL_BSP_*` environment variables as process-wide fallbacks. A larger finite
  queue does not guarantee lossless telemetry.
- Operational logging configuration and sink lifecycle are available, but broad
  operational log coverage across commands is not yet available.
